Claude Fable 5.1 토큰 사용량이 너무 빠른 이유와 줄이는 방법

Claude Fable 5.1을 사용한 뒤 5시간·주간 사용량이 빠르게 소진된다는 경험담이 나오고 있습니다. 실제 Reddit 사례와 공식 문서를 통해 토큰 사용량이 커지는 이유와 Claude Code에서 바로 적용할 수 있는 프롬프트 설정을 정리합니다.

03, 2026
6 분 정도

Claude Code에서 새로운 모델이 나오면 보통 기대하는 것은 비슷합니다.

코딩을 더 잘하고, 복잡한 작업을 더 오래 수행하고, 한 번에 더 많은 일을 끝내는 것입니다.

그런데 최근 공개된 Claude Fable 5.1을 사용한 개발자들 사이에서는 조금 다른 이야기가 나오고 있습니다.

“성능은 좋은데 사용량이 너무 빨리 사라진다.”

실제로 Reddit에서는 Fable 5.1을 사용한 뒤 평소에는 도달하지 않던 사용량 제한에 처음 도달했다는 경험담들이 올라오고 있습니다. 단순히 새 모델이 토큰을 많이 사용하는 걸까요? 공식 문서를 확인해보면 조금 다른 이유가 보입니다.

Fable 5.1을 사용했더니 하루에 5시간 제한을 두 번 채웠다

9월 2일 r/ClaudeCode에 Fable 5.1의 토큰 사용량을 주의해야 한다는 글이 올라왔습니다. 작성자는 Fable 5.1의 성능 자체보다는 작업 방식에 주목했습니다.

댓글에는 곧바로 비슷한 경험담이 이어졌습니다. 한 사용자는 Fable 5.1을 사용하면서 평소 한 번도 채우지 않았던 5시간 사용 제한을 하루 동안 두 번이나 소진했다고 설명했습니다. 또 다른 사용자는 Max 20x 요금제를 사용하면서 하루 만에 주간 사용량의 75%를 사용했다고 했습니다.

반대 경험도 있습니다. 6시간 이상 사용했지만 주간 Fable 사용량이 약 29%였다는 사용자도 있었고, 이전 모델보다 낮은 effort에서도 좋은 결과가 나온다는 의견도 있었습니다.

공식 문서에 힌트가 있습니다

Anthropic의 Fable 5.1 프롬프트 가이드를 보면 꽤 중요한 내용이 나옵니다. Fable 5.1은 작업을 수행하면서 요청받은 부분뿐 아니라 주변 코드까지 같이 수정하거나, 필요하다고 판단하면 요청하지 않은 동작을 확장하거나 테스트 파일을 더 추가할 수 있다고 설명합니다.

개발자 입장에서는 얼핏 좋아 보입니다. 예를 들어 버튼 하나를 수정해달라고 했는데 AI가 관련된 버그까지 발견해서 같이 고쳐준다면 편합니다. 문제는 작업량입니다.

# Editing Rules

- 요청한 작업 범위만 수정합니다.
- 요청하지 않은 리팩터링은 진행하지 않습니다.
- 기존 문제를 발견해도 현재 작업에 반드시 필요한 경우가 아니라면 수정하지 않습니다.
- 추가 문제는 작업 완료 후 별도로 보고합니다.
- 작은 변경에서는 파일 전체를 다시 작성하지 않고 필요한 부분만 수정합니다.
- 기존 테스트가 있다면 우선 활용하고 불필요한 테스트 파일을 추가하지 않습니다.

“어떻게 토큰을 덜 쓰게 할까?”

에 가깝습니다. 모델이 똑똑해질수록 AI에게 설명을 덜 해도 되는 것처럼 느껴집니다. 그런데 실제로는 반대인 부분도 있습니다.

능력이 커진 만큼 작업 범위를 더 명확하게 지정해야 할 때가 있습니다.
